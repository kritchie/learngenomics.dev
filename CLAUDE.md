# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

learngenomics.dev: a Docusaurus 3 site (React 19, Node.js 20+, CI uses Node.js 26) that teaches genomics, with a focus on cancer, to software engineers. The content is Markdown in `docs/`. Most figures are SVGs that Python scripts in `scripts/` generate. `README.md` and `scripts/README.md` are the authoritative contributor docs.

## Commands

```bash
npm install
npm start                 # dev server, http://localhost:3000
npm run build             # static site into build/; fails on broken links (onBrokenLinks: "throw"); broken anchors only warn — check the output
npm run serve             # preview build/

# Accessibility suite (Playwright + axe). Needs a fresh build: routes come from build/sitemap.xml.
npx playwright install chromium        # once
npm run build && npm run test:a11y     # serves build/ on port 3100
# One spec / one project / one test:
npx playwright test tests/a11y/figures.spec.js --project light-desktop --project dark-desktop
npx playwright test tests/a11y/pages.spec.js --project light-desktop -g "page /docs/before-you-begin"

# Figures (Python)
python3 -m venv scripts/.venv
scripts/.venv/bin/pip install -r scripts/requirements.txt
scripts/.venv/bin/python scripts/generate_figure_1.3.py           # one figure; --out-dir DIR to write elsewhere
for f in scripts/generate_figure_*.py; do scripts/.venv/bin/python "$f" || break; done
scripts/.venv/bin/pip install -r scripts/requirements-checks.txt  # RDKit, for the check below
scripts/.venv/bin/python scripts/check_figure_chemistry.py        # exits 1 on failure

node scripts/generate_social_card.cjs   # static/img/social-card.png; reads .docusaurus/globalData.json, so build first
```

There is no linter or unit-test runner. CI (`.github/workflows/CI.yml`) runs build, then the a11y suite, then a deploy to GitHub Pages (only on a push to `main`, and only if a11y passes).

## Architecture

### Content and Sidebar
- `sidebars.js` autogenerates the sidebar from `docs/`. The numeric prefixes on folders and files set the order. Each chapter has a `_category_.json` (label, position). URLs drop the prefixes (for example `docs/02-cancer-biology/01-what-is-cancer.md` → `/docs/cancer-biology/what-is-cancer`).
- Each page has `title` and `description` front matter.
- MDX pages can import `@site/src/components/{ProteinViewer,ProteinPaint,YouTube}`.

### Figure Pipeline (spans plugins/, scripts/, src/, tests/)
1. `scripts/generate_figure_<N.M>.py` defines `NAME` and `fig()`, then calls `figures.core.main(NAME, fig)`. This writes `docs/images/<N.M>-<slug>.svg` with embedded subset fonts (WOFF2). The output is deterministic. **Do not hand-edit a generated SVG.** Edit the script and regenerate. The exceptions (Illustrator exports, which you edit directly) are listed in `scripts/README.md`.
2. Shared code goes in `scripts/figures/`, because script file names contain dots and cannot import each other.
3. `plugins/remark-figures.js` (a remark plugin, registered in `docusaurus.config.js`) turns a paragraph with only `![alt](../images/N.M-x.svg "Caption")` into `<figure id="figure-N-M">` with a numbered `<figcaption>`. **The number comes from the file name**: to renumber, rename the script, its `NAME`, the SVG and every reference in `docs/`. The plugin also adds a "tall" class when the viewBox height/width is greater than 1.05.
4. For SVG figures, remark-figures also sends a second import through `plugins/figure-dark-loader.js`, which calls `plugins/figure-dark.js` to remap colors for the dark page (`#170d10`). The remap keeps hue and inverts WCAG contrast; bright accents keep their color. `data-dark-fill` and `data-dark-deep` in the SVG control this remap. CSS shows the copy that matches the theme. Draw every figure for a white page.
5. `src/theme/MDXComponents.js` overrides `figure` so that `#figure-N-M` anchors register with the broken-link checker.
6. `tests/a11y/figures.spec.js` renders each figure in both themes and checks text contrast against the pixels behind it (4.5:1, or 3:1 for large text). Use the `*_TEXT` colors / `T()` from `figures.core` for text. Do not fade groups that contain labels.

### Quizzes
- Each chapter has a `quiz.md` without a number prefix. Autogenerated sidebar sorts docs that have no position last. `docs/final-quiz.md` is a top-level doc after the chapters. The front matter has `quiz: true`.
- The components (`src/components/Quiz/`) are global through `src/theme/MDXComponents.js`: `<Quiz>`, `<Question [multiple] [answer={bool}]>`, `<Option [correct]>`, `<Explanation>`. The authoring format is in the README. `Question` validates its options during render, so a malformed question throws and `npm run build` fails.
- Explanations are always in the SSR HTML (`hidden` until the reader checks) so the build link checker sees their links.
- Scores are in `localStorage` (`learngenomics:quiz-scores`, in `Quiz/scores.js`). Quiz pages are never marked "read".

### Guide Map
`plugins/guide-map.js` reads the docs sidebar in `allContentLoaded`, counts words per page (200 wpm), and publishes global data (`guide-map`). Quiz docs are not in `pages`: they go to `chapter.quiz` and `finalQuiz` (with a question count), so they are not in page counts or reading times. It also injects a head script that restores the collapsed state of the band from `localStorage`. The home page `GuideMap`, the `GuideBand` over each doc (added in `src/theme/DocRoot/Layout`) and `GuideLocator` consume this data. The social-card script reads it from `.docusaurus/globalData.json`.

### Theme Overrides
`src/theme/` contains swizzled components: `DocRoot/Layout` (adds GuideBand), `DocItem/Layout` (one centered reading column and a right rail with the TOC and `DocSourceLinks`), `DocItem/Content`, `DocItem/Footer`, `DocBreadcrumbs` and `MDXComponents` (Markdown tables become focusable only when they scroll horizontally). Prism themes are in `src/prism/themes.js`.

### Accessibility Suite
`tests/a11y/scan.js` gives a fixture that forces the theme and blocks YouTube, ProteinPaint and analytics. It fails on any WCAG 2.2 A/AA violation. There are 4 projects: light/dark × desktop (1280 px)/mobile (390 px). `states.spec.js` covers interactive states (mobile menu, collapsed band, 3D viewer, reading progress, expanded guide-map chapter, answered quiz). Chromium uses SwiftShader for WebGL (3Dmol viewer).

## Writing Conventions (from README)
- Plain prose for a newcomer to biology.
- Every factual claim needs an inline source link, for example `([Knudson, 1971](https://doi.org/10.1073/pnas.68.4.820))`.
- Title Case headings. American spelling. Bold a term only where the guide first introduces it.
- Every figure has the copyright line (`figures.core.COPYRIGHT`).
